# Advanced Sharing Implementation Plan

> **For agentic workers:** Use superpowers:test-driven-development. Independent API and desktop-routing tasks may run in parallel under superpowers:dispatching-parallel-agents; the main worker owns UI and integration.

**Goal:** Let Spola users understand and manage link and named sharing from their desktop file manager.

**Architecture:** A synchronous, GTK-independent Koofr sharing client exposes immutable snapshots; the native dialog runs calls asynchronously and reloads after mutations. Desktop menu adapters open that dialog, preserving compatible command entry points without silently publishing files.

**Tech Stack:** Python standard library, GTK 4, libadwaita, unittest, existing gettext tooling.

**Spec:** `docs/superpowers/specs/2026-10-29-sharing-design.md`

## Global Constraints

- No new runtime dependencies; no change to sync/rclone behaviour.
- English source strings and Italian translations; Linux and Windows support.
- Opening/copying is read-only; inviting and publishing require explicit UI actions.
- No real invitations or publication of user files during tests.
- Do not log passwords; finite network timeouts and no write retries.

## Review Focus

- Access inherited from a parent remains visible and cannot accidentally be broadened or removed on a child.
- A mandatory password, unavailable plan option, expired link or partial API failure never produces a false success or misleading copy action.
- Previously assigned custom and unknown permissions survive unrelated changes; owners cannot be demoted/removed.
- Closing during a request and opening another dialog do not apply stale callbacks or keep UI blocked.
- Older extensions/CLI entry points cannot silently create a public link.

## Task 1: Sharing API and domain model

Files: create `src/spola/sharing.py`, `tests/test_sharing.py`.

Interfaces: `Client(user, password, mount_id)` with `load(path) -> Snapshot`, `create_link(path) -> Link`, `update_link(link, *, password_mode='keep', password='', valid_to=UNCHANGED, downloadable=UNCHANGED) -> Link`, `revoke_link(link)`, `invite(path, email, permissions)`, `update_member(access, member_id, permissions)`, `remove_member(access, member_id)`.

Data: `Link(id, mount_id, path, url, has_password=False, password='', password_required=False, valid_from=None, valid_to=None, downloadable=True, counter=0)`; `Member(id, name, email, permissions, owner=False)`; `Access(mount_id, path, is_dir, members, can_manage)`; `Snapshot(path, name, is_dir, link=None, access=None, inherited=(), inherited_links=(), can_create_link=False, can_invite=False)`. Add defaults to facilitate fixtures. `SharingError` carries a user-readable sanitized message. `permissions_for_role(role, existing=None)` and `role_for_permissions(permissions)` implement viewer/editor/custom without discarding unrelated keys.

## Task 2: Desktop routes

Files: `app.py`, `dbus_service.py`, `explorer.py`, `file_managers.py`, `extensions/spola-files.py` and their tests.

Interface consumed by app: `SharingDialog(window, remote_path)` from `sharing_dialog.py`; it obtains credentials/mount from `window.engine`. Introduce `_share(path)` resolving local pairing and exclusions before presenting it. Windows `--share` and D-Bus `Share` open it; `--copy-link` and `ShowShareLink` route to the dialog. Legacy `CreateShareLink` only returns an existing usable unprotected link and otherwise opens the dialog and reports that explicit sharing is needed. No call to `rclone.share_link` remains in desktop paths. Version-gate the extension's new action with a compatible fallback.

## Review and validation notes

- Independent review closed the implicit READ grant, incomplete membership
  metadata, unrenderable link timestamps and custom-filter interpretation
  findings. Existing-share management also respects explicit permission denials.
- Regression tests were observed failing before each correction. The final
  focused review run passed 110 tests, with three Windows-only skips.
- The supported filter subset was compared against rclone 1.75.2, including
  340 additional file/directory comparisons from the reviewer, with no
  mismatches. Unsupported advanced syntax is refused explicitly.
- Native dialogs were inspected with fixture data in English and Italian.
  The calendar dialog renders without GTK/Adwaita warnings using Cairo;
  the final GTK/routes run passed 28 tests without skips.
- Italian gettext validation: 747 translated messages, no fuzzy or untranslated
  entries. Ruff, desktop-entry and AppStream validation passed.
- Live Koofr validation was limited to reading the unshared work folder and its
  ancestors. Invitations, public links and permission writes used fake HTTP
  responses only; no user files were published during validation.
- Delivery version: 0.3.36. Upload requests and a global sharing inventory
  remain outside this first delivery, as agreed in the design.

Final integrated suite: 435 tests in 408.716 seconds, all passed; 20 Windows-only skips on Linux. Native Windows verification runs in the release workflow.


The initial v0.3.35 Linux publication was blocked by its test gate: the new
rclone filter comparison inherited the CI variable RCLONE_VERSION=1.75.2,
which rclone interprets as its boolean --version flag. The failure was
reproduced locally (14 subcases); the test now uses the existing clean_env()
helper, as production rclone calls do. The focused 51-test run passes with
that same CI environment (three Windows-only skips). Application behavior is
unchanged. The published tag remains immutable; v0.3.36 carries the correction.
